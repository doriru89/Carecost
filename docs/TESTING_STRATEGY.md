# Testing Strategy

CareCost uses a TDD-first workflow for behavior changes and major refactors.

## TDD policy

For behavior-affecting work:

1. Write a failing test first (Red).
2. Implement minimal code to pass (Green).
3. Refactor with tests green (Refactor).

Applies to new features, bug fixes, data transformations, and behavior-sensitive refactors.

## Test pyramid

### Backend

- Unit tests for pure logic under `backend/tests/unit/`.
- Integration tests for DB and route contracts under `backend/tests/integration/`.
- API-level regression tests for auth, providers, estimate, and profile flows.

### Frontend

- Unit/component tests with Vitest + React Testing Library.
- Focused route/guard/profile tests for critical flows.
- Optional Playwright smoke tests for high-value paths.

## Coverage gates

Coverage gates are enforced in CI:

- Backend target minimum line coverage: 75%.
- Frontend target minimum line coverage: 75%.

Thresholds should be raised gradually as coverage stabilizes.

## Local test commands

Backend:

```bash
cd backend
pytest --cov=app.config --cov=app.services.intake --cov=app.services.jwt_auth --cov=app.services.plan_rules --cov=app.services.pricing --cov=app.services.safety_crisis --cov=app.services.scenario_to_bundle --cov-report=term-missing --cov-report=json:coverage-backend.json --cov-fail-under=75
```

Frontend:

```bash
cd frontend
npm test -- --coverage --coverage.thresholds.lines=75
```

Optional relaxed local run:

```bash
RELAXED_COVERAGE=1 npm run test:coverage
```

## Quality dashboard data contract

`/quality` reads a machine-readable status document containing:

- latest run status
- backend/frontend coverage percentages
- failing tests (if available)
- commit SHA and timestamp

This document is generated by CI and can also be generated locally for debugging.
